3) Access API without token → 401 Unauthorized.

SESSION SECURITY
4 Session identifiers and renewal: Session ID renewal on re-authentication. RETAIN Working. Every login creates a fresh session token. When you log out, the old token is deactivated. Password reset also kills all existing sessions so the user has to log in again. 1) Login → note the token → logout → login again → different token.
2) Reset password → old tokens return 401.
5 Session and cookie protection: Secure and HttpOnly cookies. REMOVE Not applicable. Our system doesn't use cookies at all — it uses Bearer tokens sent through the Authorization header instead. Since there are no cookies, Secure/HttpOnly cookie settings don't apply here. 1) DevTools → Network → no Set-Cookie headers found.
2) DevTools → Application → Cookies tab is empty.
3) API requests use Authorization: Bearer header.
6 Session expiry and revocation: periodic termination, inactivity logout and no identifiers in URLs or logs. RETAIN Working. Sessions expire after 30 minutes of inactivity (configurable in Settings). When expired, the user gets a 401 and has to log in again. Tokens are not stored in URLs or audit logs. 1) Stay idle past timeout → next request returns 401.
2) Change timeout in Settings → confirm new value applies.
3) Check audit_logs → no session tokens stored.
ACCESS CONTROL

Deputy Officer has full access, Team Leader can manage incidents/schedules, Kagawad is view-only, and Tanods can only see their own data. All 80+ routes are protected. 1) Login as Kagawad → try to create incident → 403.
2) Login as Team Leader → try to delete user → 403.
3) Login as Deputy Officer → all operations work.
4) Tanod A tries to access Tanod B's data → 403.
8 Privileged actions and account governance: administrative data entry and account management separated from official view-only analytics; fail-secure decisions. RETAIN Working. Only Deputy Officer can manage users, change settings, and view audit logs. Kagawad only gets read-only access to analytics. If auth fails, the system defaults to blocking access (fail-secure). Deletes use soft-delete so records can be restored. 1) As Kagawad → no edit/delete buttons visible.
2) As Kagawad → manually call POST /api/users → 403.
3) Delete a record → confirm it goes to archive, not permanently removed.
4) Invalid token → returns 401.
INPUT AND QUERY SECURITY
9 Input validation and safe transaction processing: Server-side allow-list validation of coordinates and text. RETAIN Working. All inputs are validated server-side using Joi schemas. Coordinates must be within valid ranges, locations are checked against an allow-list, and text fields have max-length limits. Extra/unknown fields are automatically stripped. 1) Submit invalid latitude (999) → returns 400.
2) Submit fake location → rejected.
3) Send extra fields → they get stripped out.
4) Submit username over 50 chars → returns 400.
10 Browser output and request protections: contextual encoding for Leaflet/HTML. RETAIN Working. We have an escapeHTML() function that sanitizes user input before displaying it in the browser. It's used across all frontend files. The server also sets X-Content-Type-Options: nosniff to prevent MIME sniffing. 1) Create incident with <script>alert('xss')</script> → shows as plain text, not executed.
2) Check response headers → X-Content-Type-Options: nosniff is present.
11 Database and injection protections: parameterized queries. RETAIN Working. All database queries use parameterized queries with ? placeholders. No SQL string concatenation anywhere in the code. This prevents SQL injection attacks completely. 1) Try SQL injection on login (admin' OR '1'='1) → returns "Invalid username or password."
2) Search with SQL special characters → no injection happens.
12 Upload and file-processing protections: disabled execution in upload directories. RETAIN Working. File uploads use multer with a MIME type allow-list (images and video only), server-generated filenames, and a 10 MB size limit. Uploaded files need a signed token to access them, and the token expires after 60 seconds. MIME-only check is spoofable though — see A2 for the fix. 1) Upload a .txt renamed to .jpg → gets rejected.
2) Access uploaded file without token → 403.
3) Wait 60s and try again with same token → 403 (expired).
